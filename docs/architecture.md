# 架构与维护约束

## 产品与领域边界

TabNest 是本地优先的新标签页扩展。UI 通过仓库操作 Chrome 书签，不维护第二套书签树。“书签拼图 / 文件夹”是呈现模式；真实目录始终由 Chrome 的节点 ID、parentId、folderType 和 unmodifiable 决定。不可向不可见的根节点 0 写入，不能重命名、移动、删除系统目录，受管理节点只读。

主页面组合 shadcn 的 Tabs、ToggleGroup、Card、Avatar、ContextMenu、DropdownMenu、Collapsible、Popover、Command、Dialog、AlertDialog、Field、Switch、Slider、Tooltip、Badge、Table、Progress 和 Sonner。领域规则不写进 `components/ui`，品牌色通过语义令牌传入卡片。

EditorDialog 统一书签、文件夹和导入的布局与提交交互：标题和操作区固定，表单内容在必要时独立滚动；提交禁用、关闭保护和忙碌状态由同一组件管理，验证与数据写入仍归各编辑器及仓库层。文件夹选择器与新建入口组合官方 ButtonGroup，明确使用可收缩列而不是将 `w-full` 与固定宽按钮相加；Popover 随触发器宽度布局，并限制在视口可用空间中。

App 负责组合数据、两种书签视图和工具弹窗。AppHeader 管理顶部入口，use-bookmark-search 管理搜索面板状态、异步索引和完整结果快照，use-library-actions 管理业务操作与互斥的编辑／删除／导入确认状态，LibraryDialogs 负责呈现。搜索结果使用自然网格，HeatMap 只处理热度布局。统计使用 Table、Progress 和可操作的重复书签入口，不再依赖图表库。

主导航在 `settingsReady` 后首次呈现选中态，偏好读取期间保留导航占位，不渲染默认模式的选中态。首次挂载不播放切换过渡，用户切换继续使用正常反馈；内部 `heat / zones` 存储值不变。输入组件以独立的 `focus-border` 语义令牌表示一像素焦点边框，不叠加外部光环，保留自动聚焦与键盘操作。

主视图切换保留 shadcn/Radix Tabs、TabsList、TabsTrigger、TabsContent 的键盘规则。选中底座滑动，单个实际内容树先用 90ms 淡出，在完全透明时挂载目标视图，尺寸和有效拼图准备好后用 150ms 淡入；不使用浏览器 View Transition 快照，也不叠加两套页面。顶部保持稳定，切换期间固定容器高度并暂停内容操作，完成后释放；每种模式记忆滚动位置。快速来回切换捕获当前透明度并取消过期动画，衔接最新目标。慢 Worker 不会提前露出空拼图。Chrome 114 使用同一路径；首次打开不播放模式切换，减少动态效果直接应用终态。

新标签页在 React 载入前通过本地同步脚本确定亮暗背景和 color-scheme，符合 MV3 的本地脚本策略。字体预加载，首屏数据与可见布局准备完成后，整个页面只做一次 180ms 透明度过渡；加载占位不在短暂读取阶段闪现。后续切换与首次打开分别控制，减少动态效果直接显示。启动异常的 3 秒兜底只解除展示屏障，不改变数据。

## 数据与失败恢复

存储文档包含 `schemaVersion`、`revision`、`updatedAt`、`data`。当前为 schema 1；升级时应新增明确迁移分支，并保留未知版本拒写行为。每个键最多保留最近三次迁移或恢复前的原始数据，恢复副本位于 `tabnest:recovery:<原键>`。

Web Locks 按存储键和书签写操作串行化同源页面的操作；设置只提交变更字段，计数采用读取后合并。降级队列只能保护当前页面，不能替代支持 Web Locks 的正式浏览器。UI 丢弃过时请求，失败设置恢复到已确认状态；异常书签数据不会被样例数据覆盖。

编辑时比较旧 title、url、parentId，避免覆盖已发现的并发修改。需要先移动再更新的操作在失败时尝试恢复原位置；无法恢复时报告部分成功。删除文件夹前校验确认时的内容快照。Chrome API 没有事务或条件更新，因此其他扩展及浏览器原生管理器在校验后的极短窗口内仍可能修改数据，不能声称强事务一致性。

导入在一个全新文件夹中完成。校验全部数据后才写入；发生失败时只清理本次导入创建的节点。如果导入目录被其他操作加入了新内容，保留目录并报告部分导入，避免误删已有内容。

## 布局与性能

界面以黑白与中性灰语义令牌为主，彩色仅集中在拼图块和网站图标；必要错误沿用组件的 destructive 状态。设置 Dialog 内完整组合 CardHeader、CardContent、CardFooter、Tabs、Field、ToggleGroup、Switch、Slider、Badge 与 Separator；容器固定高度，三组内容 forceMount 共享空间，非活动内容 inert，保留 Radix 键盘规则。选中背景与内容淡入使用短时间线，主题颜色过渡不触发初次导航动效。

拼图卡片使用 shadcn 的 Card、CardHeader、CardTitle、CardDescription、CardContent 组合，背景跟随黑白语义主题：亮色为白色哑光面，暗色为石墨灰，使用细内边缘和中性图标底座。已移除彩色色板、渐变和装饰图案；品牌颜色仅保留在网站图标。热度面积算法与材质分离，文件夹视图继续使用固定规格的中性卡片。悬停和按压只轻微改变底色，不读取指针几何、不移动边界、不播放点击外圈动画；键盘焦点与选中标记保持可见，并尊重减少动态效果偏好。中文标题使用 500 字重，避免 Windows 将中间字重匹配到过粗的粗体。

主页面保留 document 原生滚动，以 `scrollbar-width: none` 隐藏滚动条，并为较旧 Chrome 提供 `::-webkit-scrollbar` 回退；不同时设置 `scrollbar-gutter: stable`。稳定 gutter 与 Radix 的滚动锁宽度补偿会重复占位，使背景缩窄并触发云图重新排布。保持 Radix 原生的背景滚动锁和焦点管理，不覆盖它的 body margin/padding，也不将主页面改成嵌套滚动容器。书签卡片的 `scroll-margin-top` 为键盘定位结果预留顶部导航高度；不在根节点设置滚动内边距，避免菜单焦点返回固定导航时将页面滚回顶部。

浏览器运行器移除了 Puppeteer 默认的 `--hide-scrollbars`，避免测试环境掩盖 Windows 经典滚动条问题。`test:scroll` 在真实滚动条环境逐帧检查菜单、Dialog、AlertDialog 和嵌套文件夹选择器切换期间的卡片位置、画布宽高和滚动位置，同时检查模态焦点、背景锁定、搜索键盘定位和首尾内容可达性；预览与实际安装的扩展使用独立测试书签。

书签 HoverCard 使用受控状态：右键菜单切换时关闭预览，已有菜单或模态弹窗时拒绝延迟的预览打开请求，避免其抢占浮层顺序并吞掉用于关闭当前操作的 Esc。

拼图采用有边界的连续矩形切分。每个固定区域最多 24 张卡片；热度权重为 2 + √累计点击，点击只重新分配目标所在区域的面积，不增加画布高度。优先移动既有切分线；增长被切分结构限制时，按共享边界、距离和热度从近邻取得空间，尝试确定性的区域内切分候选。所有候选必须由树完整重建，面积总和加间距恰好等于区域面积，不能以散放小卡片留下空洞。目标面积不减，最小卡片 56 × 56px，长宽比不超过 2:1；任一边到达 56px 时另一边也为 56px。标准缩放下最大面积为 max(360², min(520², 区域面积 × 30%))，最长边不超过 700px，具体边界由 heatLimits 随区域和缩放计算。约束求解还使用宽高和的保守线性上限；无可行增长时保留最后有效布局，计数继续保存。

热度份额使用有上下限的共同分配：qᵢ = clamp(λ × (2 + √cᵢ), 56², 最大面积)，二分 λ 使总和等于当前矩形面积总和；饱和卡片的多余份额重新分配。首次加载一次性拟合全部历史热度。单次点击请求 max(当前面积 + 本次份额增量, 最新累计份额)，避免被挤到 Logo 的热门卡片只能按小面积微量增长。真实共享边界要求沿边投影重叠，邻接图距离优先，再比较低热度、几何距离与稳定索引。既有树能完成约 70% 请求增长时保留连续边界动画，否则尝试有限个确定性候选；这是局部优化而非全局最优保证。公式、约束及停止条件见 [算法设计](heat-algorithm-2.7.0.md)。

冷门卡片点击前后份额都在最低面积时，使用热度增量请求有限额外空间，仍接受相同几何校验，避免连续点击却保持零增长。v8 快照额外记录 allocationVersion；缺少标记的有效旧缓存在首次打开按保留计数校正区域内部面积，区域外框与无热度区域保持，不要求用户清理缓存或先点击。

常规集合使用完整页面的可用宽高，区域均衡分组避免最后一个小区域留下过多空白。一至四张卡片保持紧凑，允许必要留白；大量书签保持现有隐藏滚动条和原生连续滚动。缓存 tabnest:heat-layouts:v8 独立于书签与计数，保存区域、树、绝对切分坐标及热度快照，最多四份和 4 MB；URL、宽高、密度或缩放改变后可重新生成。校验时要求缓存矩形与树重建完全一致。损坏和旧缓存不改变书签；新版写入成功后清理 v6/v7 的可丢弃布局缓存。Web Locks 串行化缓存写入，新页面恢复有效快照；已打开页面按持久化热度协调，避免缓存事件重建会话。

边界共用 240ms 时间线，不通过 transform 缩放标题或图标。同一切分结构采用矩形插值，逐对检查起终点的共同分离方向；面积的二次函数还检查区间内极值。改变切分结构且不满足安全插值时，受影响卡片先淡出，中点透明时切换有效矩形，再淡入；任何显示帧都使用有效几何，不让交叉矩形经过页面。连续点击衔接当前矩形和透明度，弹窗、菜单和多选冻结，减少动态效果直接应用有效终态。heat-motion 的帧函数与真实 Hook 共用，测试覆盖两个过渡分支。主线程和 Worker 共用 calculateHeat、HeatInput、HeatResult 和校验器，请求携带协议版本及上一份有效快照。Worker 超时、异常或消息失败回退本地计算。

Worker 返回快照经统一校验后使用缓存中的同一份对象，避免每次点击重新校验全部区域。动画只校验变化区域，未变化卡片使用 React.memo；最近打开的网址映射按书签集合缓存，编辑或删除后的新集合会重新建立映射。

历史热度初始化只检查既有树与两种顺序，限制投影次数，不运行点击时的完整搜索和梯度细化。相同区域参数及计数分布共享最多 32 份不含书签对象的不可变热度几何模板；单次点击保持完整局部求解。性能验收同时覆盖无热度和大量历史热度，避免将新安装数据的表现误当成长期使用表现。

新标签页不预热搜索索引，打开搜索时才加载拼音模块；计算 Worker 使用 ES 模块和动态导入。Worker 和本地搜索索引闲置 30 秒后释放，下一次搜索重新准备索引。书签卡片继续虚拟渲染，不挂载全部收藏。当前标签页导航将计数和最近打开提交给按事件启动的 MV3 service worker，页面立即跳转；记录使用现有独立文档和 Web Locks，无新增权限、网络或常驻业务服务。

## 2.7.1 区域执行与质量记录

区域规划先确定完整画布外框，热度求解复用原有局部算法。HeatSession 按书签 ID 和网址建立区域索引，可见区域及预渲染范围同步求解，其他区域由 Worker 分批完成；滚动到未完成区域时使用同一求解函数。协议 v3 带会话、数据和请求修订号，取消任务与旧结果不能覆盖最新计数。仅完整快照进入 v8 缓存；跨页缓存事件不会重建当前会话，重新打开时恢复有效快照。

动画持有挂载区域的矩形，弹窗规格变化同样冻结。空查询不依赖热度排序，搜索面板关闭后空闲 30 秒释放计算 Worker 和索引。前台恢复重新读取持久化状态。

恢复格式 tabnest-recovery v1 与普通备份分开；导出直接读取原始存储。导入先校验各部分，损坏与未知版本不写回，计数采用最大值合并。最外层错误边界包围主题和应用。

构建身份摘要覆盖源码、依赖锁和构建输入，不包含生成文档和时间戳。发布报告记录最终 ZIP SHA-256，验收批次绑定该候选包。本地先生成一次候选包，各平台解包使用同一版本；发布聚合拒绝混用批次与构建。仓库 CI 已关闭。
