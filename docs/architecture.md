# 架构与维护约束

## 产品与领域边界

TabNest 是本地优先的新标签页扩展。UI 通过仓库操作 Chrome 书签，不维护第二套书签树。“书签拼图 / 文件夹”是呈现模式；真实目录始终由 Chrome 的节点 ID、parentId、folderType 和 unmodifiable 决定。不可向不可见的根节点 0 写入，不能重命名、移动、删除系统目录，受管理节点只读。

主页面组合 shadcn 的 Tabs、ToggleGroup、Card、Avatar、ContextMenu、DropdownMenu、Collapsible、Popover、Command、Dialog、AlertDialog、Field、Switch、Slider、Tooltip、Badge、Table、Progress 和 Sonner。领域规则不写进 `components/ui`，品牌色通过语义令牌传入卡片。

EditorDialog 统一书签、文件夹和导入的布局与提交交互：标题和操作区固定，表单内容在必要时独立滚动；提交禁用、关闭保护和忙碌状态由同一组件管理，验证与数据写入仍归各编辑器及仓库层。文件夹选择器与新建入口组合官方 ButtonGroup，明确使用可收缩列而不是将 `w-full` 与固定宽按钮相加；Popover 随触发器宽度布局，并限制在视口可用空间中。

App 负责组合数据、两种书签视图和工具弹窗。AppHeader 管理顶部入口，use-bookmark-search 管理搜索面板状态、异步索引和完整结果快照，use-library-actions 管理业务操作与互斥的编辑／删除／导入确认状态，LibraryDialogs 负责呈现。搜索结果使用自然网格，HeatMap 只处理热度布局。统计使用 Table、Progress 和可操作的重复书签入口，不再依赖图表库。

主导航在 `settingsReady` 后首次呈现选中态，偏好读取期间保留导航占位，不渲染默认模式的选中态。首次挂载不播放切换过渡，用户切换继续使用正常反馈；内部 `heat / zones` 存储值不变。输入组件以独立的 `focus-border` 语义令牌表示一像素焦点边框，不叠加外部光环，保留自动聚焦与键盘操作。

## 数据与失败恢复

存储文档包含 `schemaVersion`、`revision`、`updatedAt`、`data`。当前为 schema 1；升级时应新增明确迁移分支，并保留未知版本拒写行为。每个键最多保留最近三次迁移或恢复前的原始数据，恢复副本位于 `tabnest:recovery:<原键>`。

Web Locks 按存储键和书签写操作串行化同源页面的操作；设置只提交变更字段，计数采用读取后合并。降级队列只能保护当前页面，不能替代支持 Web Locks 的正式浏览器。UI 丢弃过时请求，失败设置恢复到已确认状态；异常书签数据不会被样例数据覆盖。

编辑时比较旧 title、url、parentId，避免覆盖已发现的并发修改。需要先移动再更新的操作在失败时尝试恢复原位置；无法恢复时报告部分成功。删除文件夹前校验确认时的内容快照。Chrome API 没有事务或条件更新，因此其他扩展及浏览器原生管理器在校验后的极短窗口内仍可能修改数据，不能声称强事务一致性。

导入在一个全新文件夹中完成。校验全部数据后才写入；发生失败时只清理本次导入创建的节点。如果导入目录被其他操作加入了新内容，保留目录并报告部分导入，避免误删已有内容。

## 布局与性能

材质由全局语义令牌控制：色板、边缘、高光、图标底座、阴影及动效时长独立定义亮暗值。热度面积算法与材质分离，文件夹视图继续使用固定规格的中性卡片。悬停只改变表面高光透明度和阴影，不在 pointermove 中逐次读取几何或改写样式，也不移动卡片边界；点击反馈使用短暂轮廓光，并尊重减少动态效果偏好。中文标题使用 500 字重，避免 Windows 将中间字重匹配到过粗的粗体。

主页面保留 document 原生滚动，以 `scrollbar-width: none` 隐藏滚动条，并为较旧 Chrome 提供 `::-webkit-scrollbar` 回退；不同时设置 `scrollbar-gutter: stable`。稳定 gutter 与 Radix 的滚动锁宽度补偿会重复占位，使背景缩窄并触发云图重新排布。保持 Radix 原生的背景滚动锁和焦点管理，不覆盖它的 body margin/padding，也不将主页面改成嵌套滚动容器。书签卡片的 `scroll-margin-top` 为键盘定位结果预留顶部导航高度；不在根节点设置滚动内边距，避免菜单焦点返回固定导航时将页面滚回顶部。

浏览器运行器移除了 Puppeteer 默认的 `--hide-scrollbars`，避免测试环境掩盖 Windows 经典滚动条问题。`test:scroll` 在真实滚动条环境逐帧检查菜单、Dialog、AlertDialog 和嵌套文件夹选择器切换期间的卡片位置、画布宽高和滚动位置，同时检查模态焦点、背景锁定、搜索键盘定位和首尾内容可达性；预览与实际安装的扩展使用独立测试书签。

书签 HoverCard 使用受控状态：右键菜单切换时关闭预览，已有菜单或模态弹窗时拒绝延迟的预览打开请求，避免其抢占浮层顺序并吞掉用于关闭当前操作的 Esc。

云图移除手动重排，旧 shuffleSeed 设置被忽略。分割树按书签 ID 序列与视口宽度缓存，热度变化复用分割关系，本地保留最近四个组合。云图使用单一尺寸观察器获取宽度，按数量、视口、密度和缩放推导基础高度；点击数不能直接增加画布高度。小集合尽量使用当前视窗，大集合允许连续滚动。分割算法探索有限个确定性顺序，再固定分割方向，补偿间距造成的面积差，优先满足 48 × 48px 下限与可访问性；达到最小尺寸或形状约束后允许面积饱和，不承诺任意极值下全局严格比例。

画布没有分页与数量截断。文件夹视图视图以真实根目录作为 Tabs，每个文件夹使用独立的 Card + Collapsible；卡片内部采用紧凑网格／列表，大小不受点击数影响。ResizeObserver 测量区块的自然高度，再映射到 CSS Grid 行跨度，避免将小文件夹撑到同一行最高区块的高度。区块保持原始文件夹顺序，不改写 Chrome 树；嵌套文件夹显示上级路径，每个书签只渲染一次。空根目录只出现在顶部切换中，普通空文件夹保留名称、数量和管理菜单。

新建书签和文件夹统一由顶部「＋」进入，默认使用当前根目录，可在表单中选择目标文件夹。文件夹视图工具栏只提供选择、排序和排列方式；卡片只保留一个管理菜单，不重复提供新建操作。系统根目录和只读文件夹的菜单不展示重命名、移动或删除操作；底层仓库继续校验写入权限。

旧版 activeFolderId 若指向嵌套文件夹，界面定位到其真实根目录；folderLayout 的旧 heat 值回落到 grid。collapsedSections 独立保存区块折叠状态，旧文件夹树 collapsed、tilt 字段已从运行状态移除；旧 recent 排序回落到浏览器顺序。热度模式的算法和样式保持独立。

统计、书签／文件夹编辑、设置与导入按需加载；字体与常见图标随扩展打包。发布门禁限制 ZIP 小于 2 MB、入口 JS gzip 小于 250 KB。

自动化覆盖零点击、极热、连续点击、长标题、窗口变化、刷新记忆及增删集合；逐帧验证共享边界不交叉，菜单与弹窗没有背景宽度、高度和滚动偏移。文件夹视图在常见桌面宽度采用三列，320–1920px 及 400px 短窗口分别检查亮暗主题。

性能场景覆盖 500／5000／20000 条书签与最多 2000 个文件夹，每场景五次。SectionBoard 超过 30 个区块时虚拟化文件夹；可见区块内部继续用 BookmarkGrid 虚拟化。viewport 集中订阅窗口滚动和尺寸，保留完整高度、焦点钉住和末尾键盘访问。共享目录索引保存父子关系、数量、路径与书签分组。

热度更新合并 48ms；共享边界用相同 240ms 曲线插值，内容不通过 transform 缩放。对话框、菜单、多选和拖动暂停进行中的边界动画并冻结新布局更新，关闭后应用最新结果。Worker 在千条以上处理布局、拼音索引和查询；请求 ID 与索引版本防止过期覆盖。搜索在首屏后准备索引，组件和第三方解析器按需分包，记忆化的背景视图避免输入触发整片云图渲染。

`test:ui-details` 额外覆盖长标题／长文件夹路径、亮暗主题、320–1440px 宽度与低至 400px 的窗口高度，测量表单、组合控件、Popover、固定操作区的实际边界；执行无障碍扫描，并通过延迟写入验证保存中的关闭保护、失败后的重试及新建子文件夹后保存书签的结果。这些检查与滚动稳定性检查一起纳入发布门禁。

## 备份与操作日志

JSON v5 的 BookmarkFolder.index 与 BookmarkItem.index 保存 Chrome 同级混排顺序。v2、v3、v4 继续读取，缺失索引的旧数据保留可确定顺序。ImportPlan 保存通过校验的数据、异常项和格式来源；JSON 与 HTML 共用执行器。parse5 在本地纯解析 HTML，不挂载 DOM、不执行脚本、不请求文件中的资源。

storedUrl 负责原始数据持久化，safeUrl 负责导航许可。javascript/data 等不可直接导航的地址仍可备份、复制；文件和邮件网址的点击数据也可完整备份往返。编辑器新网址仍使用较严格校验。

最近删除先按时间、20 次及 4 MB 双限制淘汰旧记录，单项超限返回独立错误，不能继续普通删除。操作日志 tabnest:operations:v1 记录导入／恢复的根 ID、开始时间和已完成数量；创建根节点后立即写检查点，每 32 项更新进度。原生 API 创建与存储检查点之间并非原子事务；不确定步骤显示待检查，按实际书签树核对现存与缺失根，不自动重放或删除。用户核对后可移除记录，恢复快照另受保护。

## 后续维护

保留回归样本、真实安装验收和打包体积门禁。兼容性报告明确区分实际运行、模拟树测试和尚未覆盖的企业策略／账号环境；不得用配置了 CI 来代替已经运行的证据。
