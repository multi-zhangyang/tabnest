# 动态拼图算法：有限空间中的热度分配

实现：`src/lib/heat-layout.ts`。页面与 Worker 调用同一个函数；真实页面回归使用生产构建，不维护另一套测试布局。

## 需要修复的问题

原算法把增长比例乘在当前面积上。卡片被其他热门卡片挤到 Logo 大小时，累计热度虽然保留，但下一次点击只能带来很小的增长。初始化又依次重放各网址的历史点击，使后处理的卡片挤小先处理的卡片。两者共同造成“点击很多却不变大”。

新版将累计热度的面积份额与当前位置分开计算：累计热度决定希望取得多少空间；现有切分决定怎样在不破坏布局的情况下取得这些空间。

## 1. 有上下限的面积份额

每个区域最多 24 张卡片，区域外框、间距与书签归属在点击期间固定。记卡片累计点击为 `cᵢ`，权重为 `wᵢ = 2 + √cᵢ`，最小面积为 `m = 56²`，最大面积为 `M`，当前矩形面积总和为 `C`。

求一个公共系数 `λ`，使：

```
qᵢ = clamp(λ × wᵢ, m, M)
Σqᵢ = C
```

夹紧后的总和对 `λ` 单调，用 48 次二分求解。到达上限或下限的卡片释放多余份额，剩余空间继续分给其他卡片。输入容量超出可行区间时先限制到 `[n × m, n × M]`；实际有效区域始终在此区间内。

首次生成布局时，一次性计算全部 `qᵢ`，共同拟合切分。初始化不按网址依次重放历史点击，也不为每个区域执行点击时的完整候选搜索：检查既有树与两种确定性顺序，限制投影次数，不做后续梯度细化。相同区域尺寸、缩放、间距和计数分布复用不可变几何模板，最多保留 32 份；不缓存书签对象。单次点击仍执行完整的局部求解。

点击前后分别计算 `qᵢ(old)` 与 `qᵢ(new)`。点击目标希望取得的面积为：

```
visibleᵢ = (√currentAreaᵢ + 6 × min(2, √Δcᵢ))² - currentAreaᵢ
requestedᵢ = min(M,
  max(currentAreaᵢ + max(0, qᵢ(new) - qᵢ(old), visibleᵢ), qᵢ(new)))
```

这同时解决两种情况：正常卡片获得本次热度增加产生的面积差；被挤小的卡片可以争取其累计热度对应的份额。其他热门卡片在下一次点击时仍可重新争取空间。份额是求解目标，几何约束可能使它不能完全实现。

冷门卡片可能在点击前后都被夹紧到最低份额。此时单纯计算份额差会得到零，出现前几次点击没有变化。两次份额都在下限时，额外请求 `min(56² / 2, C / Σw(old) × Δw)` 的面积增量；仍由同一局部求解取得邻近空间，不能突破任何硬约束。离开最低份额后恢复通常的份额差规则。

## 2. 如何从周围取得空间

先保留既有切分树，调整切分线，最小化目标的面积误差及其他卡片的变化代价。真实共享边界必须满足两项条件：边之间只隔固定间距，并且沿边的投影确实重叠。仅坐标相同或只有角点接近不算相邻。

共享边界构成邻接图，从所有点击目标进行广度优先搜索。优先向直接相邻卡片取得空间，再向区域内更远的卡片扩展；同层优先低点击，再比较几何距离和稳定索引。面积下限始终保留。

如果既有树实现至少约 70% 的请求增长，保留平滑的边界调整。否则，普通点击先沿目标的祖先切分，从小到大检查不超过 8 张卡片的子区域：固定其外框与外部切分，只调整内部结构和切分线。子区域继承外层区域的尺寸上限，不根据较小外框重新收紧上限。按真实共享边界、低热度建立让位目标，内部候选沿用同一矩形计算函数。恢复完整树后再次校验，外部卡片必须保留原矩形。

局部候选先尝试一份受控增长。普通点击的请求若在 `√面积 + 24px` 的范围内，实际增量达到 `min(max(100px², √面积), 70% × 请求增量)` 时可保留有效局部结果，避免为填满理想份额重排全区。普通点击获得的局部面积可以小于理想份额，下一次点击继续争取；历史热度落差及大批量计数更新仍要求原有约 70% 的完整请求，不能只给小幅变化。

局部范围不足时，按邻接顺序建立完整区域的让位目标，并尝试有限个确定性候选：既有树的不同调整幅度、原顺序、面积顺序、空间顺序和目标两端顺序。各候选经过约束投影和有限次细化。不能让任何本次点击目标反向缩小的候选才可参加比较。优先让更多尚未达到面积上限的目标实际增长，再比较面积误差；满足请求且能安全插值的候选优先。已达上限的副本继续保存计数，不阻止其他副本增长。

同网址的全部副本以同一份新计数作为目标，区域内共同处理，跨区域分别处理。多个目标无法共同增长时保留可行解；计数照常保存。区域外卡片坐标不动，不通过加高画布或把卡片搬到页尾腾位置。

## 3. 几何约束与覆盖

每个区域使用二叉矩形切分树：一次切分把矩形分成两个矩形及固定间距；叶节点就是卡片。任何接受的候选都由树完整重建，因此矩形与切分间距共同覆盖区域，不会出现散放 Logo 后留下空洞的情况。

所有矩形必须满足：

- `width ≥ 56`、`height ≥ 56`。
- 最长边与面积不超过 `heatLimits` 根据区域、缩放得出的上限。标准缩放最高面积 `520²`、最长边最高 `700px`；较小区域采用较小上限。
- `width ≤ 2 × height`、`height ≤ 2 × width`。
- `width ≤ 3 × height - 112`、`height ≤ 3 × width - 112`。任一边为 56 时，另一边也必须为 56。
- 求解使用保守面积约束 `a × width + height / a ≤ 2√M`，其中 `a = √(referenceHeight / referenceWidth)`；既有切分跟随参考长宽比，新结构初次投影使用 `a = 1`。由算术几何平均不等式保证面积不超过 `M`，最后再校验真实面积。

求解结果再次通过真实矩形校验。投影未收敛、尺寸不合规或目标反向縮小时拒绝候选；全部失败时保留最后有效布局。距离最大面积小于约半像素边长造成的面积差时停止调整，避免极限附近反复微动，计数继续递增。

一至四张卡片保持紧凑；通常集合铺满当前可用区域，大量书签保持原有隐藏滚动条、连续滚动和虚拟渲染。

## 4. 每一帧的安全与连续点击

边界在统一 240ms 时间线中插值，标题和图标不跟随缩放。起点与终点必须具有共同的分离方向；因为分离约束是线性的，整个插值区间也不会重叠。面积是二次函数，除端点外还检查区间内极值；尺寸、比例和下限通过线性约束保持。

重新切分可能改变卡片的相对顺序。不能安全插值的结果先淡出受影响卡片，在透明中点切换到有效矩形，然后以平滑曲线淡入。每个区域独立决定动画方式：其他安全区域继续插值，不跟着一起淡出。不会让交叉矩形在页面上移动。连续点击以当前正在显示的矩形和透明度为起点，抛弃过期动画；菜单、弹窗与多选冻结布局，关闭后应用最新热度。系统减少动态效果时直接显示有效终态。

## 5. 记忆、故障与计算范围

v8 缓存保存区域、切分线、树和对应的计数快照，最多四份、总容量 4 MB；它与书签及点击文档独立。缓存矩形必须与树重建一致。缓存损坏、旧缓存和写入失败不影响计数或书签。

缓存增加独立的 `allocationVersion: 1` 标记。已存在但缺少此标记的有效 v8 布局，在首次打开时根据保留计数重新分配区域内部面积，固定区域外框，随后记忆新布局；不要求用户先点击，也不清除书签、累计点击或最近打开。没有热度的区域保持原矩形。

一次热度更新只求解变化区域，单区最多 24 张。页面和 Worker 使用同一输入、输出、版本检查及校验器；过期结果不覆盖新请求，Worker 失败回退本地计算。动画只写入受影响卡片的边界，保持远处区域静止。

这是有硬约束的确定性局部优化，候选数量与迭代次数有限，不承诺找到所有矩形划分中的全局最优解。已有边界、比例、上下限及多目标竞争可能限制增长；停止时必须保持有效布局，不能用反向缩小、重叠或空洞来冒充增长。

## 回归依据

`tools/mosaic.test.mjs` 覆盖共同热度初始化、被挤小卡片重新增长、混合热点、极端计数、最小 Logo、上限稳定、完整覆盖及远处区域不动。匿名化的 `heat-pressure.json` 固定多热点挤压后的切分，回归局部范围、共同增长和逐帧安全。`tools/heat-pressure-check.mjs` 在真实 MV3 页面验证两个区域共同更新时，局部重排仅影响相关卡片的透明度；`tools/heat-growth-check.mjs` 检查逐次点击、历史热度和旧缓存恢复。实际数值和运行范围见 [运行记录](acceptance-2.7.1.md)。
