# 架构与维护约束

## 产品与领域边界

TabNest 是本地优先的新标签页扩展。UI 通过仓库操作 Chrome 书签，不维护第二套书签树。“分区”是呈现模式；真实目录始终由 Chrome 的节点 ID、parentId、folderType 和 unmodifiable 决定。不可向不可见的根节点 0 写入，不能重命名、移动、删除系统目录，受管理节点只读。

主页面组合 shadcn 的 Tabs、ToggleGroup、Card、Avatar、ContextMenu、DropdownMenu、Collapsible、Popover、Command、Dialog、AlertDialog、Field、Switch、Slider、Tooltip、Badge、Table、Progress 和 Sonner。领域规则不写进 `components/ui`，品牌色通过语义令牌传入卡片。

EditorDialog 统一书签、文件夹和导入的布局与提交交互：标题和操作区固定，表单内容在必要时独立滚动；提交禁用、关闭保护和忙碌状态由同一组件管理，验证与数据写入仍归各编辑器及仓库层。文件夹选择器与新建入口组合官方 ButtonGroup，明确使用可收缩列而不是将 `w-full` 与固定宽按钮相加；Popover 随触发器宽度布局，并限制在视口可用空间中。

App 负责组合数据、两种书签视图和工具弹窗。AppHeader 管理顶部入口，use-bookmark-search 管理筛选和键盘选择，use-library-actions 管理业务操作与互斥的编辑／删除／导入确认状态，LibraryDialogs 负责呈现。搜索结果使用自然网格，HeatMap 只处理热度布局。统计使用 Table、Progress 和可操作的重复书签入口，不再依赖图表库。

## 数据与失败恢复

存储文档包含 `schemaVersion`、`revision`、`updatedAt`、`data`。当前为 schema 1；升级时应新增明确迁移分支，并保留未知版本拒写行为。每个键最多保留最近三次迁移或恢复前的原始数据，恢复副本位于 `tabnest:recovery:<原键>`。

Web Locks 按存储键和书签写操作串行化同源页面的操作；设置只提交变更字段，计数采用读取后合并。降级队列只能保护当前页面，不能替代支持 Web Locks 的正式浏览器。UI 丢弃过时请求，失败设置恢复到已确认状态；异常书签数据不会被样例数据覆盖。

编辑时比较旧 title、url、parentId，避免覆盖已发现的并发修改。需要先移动再更新的操作在失败时尝试恢复原位置；无法恢复时报告部分成功。删除文件夹前校验确认时的内容快照。Chrome API 没有事务或条件更新，因此其他扩展及浏览器原生管理器在校验后的极短窗口内仍可能修改数据，不能声称强事务一致性。

导入在一个全新文件夹中完成。校验全部数据后才写入；发生失败时只清理本次导入创建的节点。如果导入目录被其他操作加入了新内容，保留目录并报告部分导入，避免误删已有内容。

## 布局与性能

材质由全局语义令牌控制：色板、边缘、高光、图标底座、阴影及动效时长独立定义亮暗值。热度面积算法与材质分离，分区继续使用固定规格的中性卡片。悬停只改变表面高光透明度和阴影，不在 pointermove 中逐次读取几何或改写样式，也不移动卡片边界；点击反馈使用短暂轮廓光，并尊重减少动态效果偏好。中文标题使用 500 字重，避免 Windows 将中间字重匹配到过粗的粗体。

主页面保留 document 原生滚动，以 `scrollbar-width: none` 隐藏滚动条，并为较旧 Chrome 提供 `::-webkit-scrollbar` 回退；不同时设置 `scrollbar-gutter: stable`。稳定 gutter 与 Radix 的滚动锁宽度补偿会重复占位，使背景缩窄并触发云图重新排布。保持 Radix 原生的背景滚动锁和焦点管理，不覆盖它的 body margin/padding，也不将主页面改成嵌套滚动容器。书签卡片的 `scroll-margin-top` 为键盘定位结果预留顶部导航高度；不在根节点设置滚动内边距，避免菜单焦点返回固定导航时将页面滚回顶部。

浏览器运行器移除了 Puppeteer 默认的 `--hide-scrollbars`，避免测试环境掩盖 Windows 经典滚动条问题。`test:scroll` 在真实滚动条环境逐帧检查菜单、Dialog、AlertDialog 和嵌套文件夹选择器切换期间的卡片位置、画布宽高和滚动位置，同时检查模态焦点、背景锁定、搜索键盘定位和首尾内容可达性；预览与实际安装的扩展使用独立测试书签。

书签 HoverCard 使用受控状态：右键菜单切换时关闭预览，已有菜单或模态弹窗时拒绝延迟的预览打开请求，避免其抢占浮层顺序并吞掉用于关闭当前操作的 Esc。

云图移除手动重排，旧 shuffleSeed 设置被忽略。分割树按书签 ID 序列与视口宽度缓存，热度变化复用分割关系，本地保留最近四个组合。云图使用单一尺寸观察器获取宽度，按照冷门卡片所需面积推导画布高度。小集合尽量使用当前视窗，大集合允许连续滚动。分割算法探索有限个确定性顺序，再固定分割方向，补偿间距造成的面积差，避免点击计数更高而面积更小。

画布没有分页与数量截断。分区视图以真实根目录作为 Tabs，每个文件夹使用独立的 Card + Collapsible；卡片内部采用紧凑网格／列表，大小不受点击数影响。ResizeObserver 测量区块的自然高度，再映射到 CSS Grid 行跨度，避免将小文件夹撑到同一行最高区块的高度。区块保持原始文件夹顺序，不改写 Chrome 树；嵌套文件夹显示上级路径，每个书签只渲染一次。空根目录只出现在顶部切换中，普通空文件夹保留紧凑添加入口。

旧版 activeFolderId 若指向嵌套文件夹，界面定位到其真实根目录；folderLayout 的旧 heat 值回落到 grid。collapsedSections 独立保存区块折叠状态，旧文件夹树 collapsed、tilt 字段已从运行状态移除；旧 recent 排序回落到浏览器顺序。热度模式的算法和样式保持独立。

统计、书签／文件夹编辑、设置与导入按需加载；字体与常见图标随扩展打包。发布门禁限制 ZIP 小于 2 MB、入口 JS gzip 小于 250 KB。

当前自动化覆盖 180 个书签的连续画布，以及 37 个书签、5 个区块在 320–1920px 宽度下的分区布局、归属关系、无重复渲染、折叠持久化和根目录切换；实际 Chrome 扩展测试覆盖原生层级和跨页更新。不宣称已完成万级书签性能验收。2.5.0 已为云图、搜索结果与大型分区加入可视区渲染；500、2000、5000 书签场景验收首屏、搜索、热度反馈、DOM 数量与末尾键盘可达性。是否引入 Worker 继续由真实基线决定。

`test:ui-details` 额外覆盖长标题／长文件夹路径、亮暗主题、320–1440px 宽度与低至 400px 的窗口高度，测量表单、组合控件、Popover、固定操作区的实际边界；执行无障碍扫描，并通过延迟写入验证保存中的关闭保护、失败后的重试及新建子文件夹后保存书签的结果。这些检查与滚动稳定性检查一起纳入发布门禁。

## 演进顺序

1. 增加 Edge、Linux、账号／本地并存目录和组织策略的实际运行矩阵。
2. 持续维护大书签库性能基线，覆盖低性能设备、更多文件夹与更大数据集，必要时引入 Worker。
3. 拖放和批量移动通过原生仓库执行；继续扩展键盘整理体验及更多失败注入场景。
4. 如加入自定义图标、主题包，使用本地资源仓库和版本化清单，避免远程执行代码。
5. 只有产品明确需要账号或同步时，才引入独立服务和适配层；不能让远程树覆盖 Chrome 书签。认证、冲突协议、删除传播、配额和迁移需独立设计与验收。

## 发布

`npm run release` 运行静态检查、数据测试、构建、浏览器交互和真实扩展验证。ZIP 只含构建目录，固定条目时间戳，校验清单、资源引用、权限、体积和解压完整性，生成 SHA-256。CI 仅保存验证产物，不自动提交商店。

回滚 UI 应保留新的存储文档；旧应用遇到未知 schema 必须拒写，不能通过降级覆盖数据。用户书签由 Chrome 管理，源码或扩展包回滚不等同于书签回滚。

## 2.5.0 操作与恢复

`batch-bookmarks` 校验最新书签快照及目标可写性，按选中顺序串行移动；Chrome 同目录移动采用移除前的插入边界。失败时恢复已完成的移动，无法安全回滚时明确报告部分成功。分区拖放支持卡片前后插入和文件夹末尾追加；只接受当前页面发起的书签拖动，不解析外部拖入内容。所有原生书签操作仍受同一 Web Lock 保护。

`recovery` 在原生删除前持久化完整子树／书签快照，保留最近 20 次操作及 4 MB 上限。失败的批量删除只展示真正消失的根节点；恢复时重新创建节点、按原索引插入，原父级消失或只读时使用可写根目录。成功恢复逐项移除记录；创建失败清理本次创建的内容，遇到外部改动时保留并报告部分恢复。此机制不模拟 Chrome 内部撤销，也不承诺原 ID、添加时间或跨扩展事务。

备份 v4 可附带 `preferences: { settings, clicks, theme }`，仍接受 v2/v3。完整导出和书签导出保留独立入口。导入偏好为显式开关，默认关闭；开启后重新映射 activeFolderId/collapsedSections，热度按规范化网址合并取较大值，主题同步到当前页面。书签已导入而偏好恢复失败时报告部分成功并关闭导入窗口，避免重试造成重复导入。

`test:product` 在实际安装的临时 Chrome 扩展中验证修饰键、中文输入法、拖放前后插入、批量移动／删除、重开页面后的恢复、完整备份及布局缓存。`test:performance` 为 500／2000／5000 书签生成量化报告；基线使用本地图标回退，不依赖外部图标网络。两项均纳入发布门禁。
